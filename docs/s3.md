# MSI Tier 2 Storage & S3 Bucket Interface

MSI Tier 2 is object storage intended for large-scale shared storage, inactive data, data sharing, and workflows that benefit from S3-compatible access. Unlike Tier 1, Tier 2 is not a mounted filesystem.

## S3 Basics and Usage

It's important to know that S3 is not actually a filesystem, but an object storage system, and S3cmd is an [API tool](https://www.geeksforgeeks.org/what-is-an-api/) for object storage. As a result, the logic you are likely more familiar with when interacting with folder structures on the command line doesn't necessarily translate to s3cmd. S3 buckets don't actually have real directory structures, so when referencing a specific file or folder on S3, you provide what may *look* like a file path, but is actually a *key prefix* used to iterate through objects with matching substrings. This means you cannot `cd` into a s3 bucket, but instead have to continuously `ls` a bucket to see what is inside each subfolder.  

For example, to list the contents of s3://luci-scratch/ABCC, it is important to include a trailing `/` (i.e. s3://luci-scratch/ABCC/). Without a trailing `/`, s3cmd will iterate through all objects containing `luci-scratch/ABCC*`, which does not include the contents of the folder itself:
```
$ s3cmd ls s3://luci-scratch/ABCC
                    DIR  s3://luci-scratch/ABCC/
```

When the trailing `/` is present, s3cmd iteratates through the bucket objects to list objects containing `luci-scratch/ABCC/*` and returns the following:
```
$ s3cmd ls s3://luci-scratch/ABCC/
                    DIR  s3://luci-scratch/ABCC/code/
                    DIR  s3://luci-scratch/ABCC/data/
2024-09-09 21:25 DIROBJ  s3://luci-scratch/ABCC/
2024-09-09 21:42   183M  s3://luci-scratch/ABCC/subjectlist.csv

```

Note that this logic also means that wildcard (`*`) doesn't work for most s3 commands

### S3cmd Usage 

Read [s3cmd usage](https://s3tools.org/usage) for full usage

`s3info -u x500` - view your s3 credentials and tier2 disk usage<br> 
`s3cmd du -H s3://bucket-name/` - check the size of a single bucket (when using commands like `du` or `ls` on large buckets, we recommend using the [s5cmd client](#Using-s5cmd))<br>
`s3cmd ls` - list all buckets you are owner on (buckets that you do not own, but have been given access to, will not appear in this list)<br>
`s3cmd rm s3://bucket-name/file` - remove a file from a bucket<br>
`s3cmd rb s3://bucket-name` - remove an entire bucket<br>
`s3cmd del --recursive s3://bucket-name/subfolder` - remove a subfolder of a bucket

Wildcard logic doesn't generally work for s3cmd commands but it does work for the `ls` and `del` commands. 

#### Making a New Bucket

Buckets intended for large shared datasets or long-term CDNI storage should generally be created and managed at the PI or group level.

For current Tier 2 allocations, bucket creation, naming requirements, and access procedures, see the [MSI File Storage documentation](https://userdocs.msi.umn.edu/storage/storage.html) and [Reducing Tier 1 Footprint at MSI](https://userdocs.msi.umn.edu/storage/archiving_data.html).

MSI's current Tier 2 workflow includes creating a bucket with `s3cmd` and assigning collaborators through a bucket policy. Because this process may change, follow MSI's documentation rather than maintaining duplicate setup instructions here.

#### Syncing Data to and from S3 Buckets
`s3cmd sync /path/to/file s3://bucket-name/` - sync a file to a bucket<br>
`s3cmd sync s3://bucket-name/file /path/to/folder/output/` - sync a file from a bucket<br>
`s3cmd sync s3://bucket-name/dir_name /destination/directory/path/ --recursive` - sync a folder from a bucket<br>
`s3cmd sync dir_name s3://bucket-name/  --recursive` - sync a folder to a bucket

- If you want to clear the prior contents of the directory that you are syncing to, include the `--delete-removed` flag to remove files that are present in the destination path but aren't present in the source path. *USE WITH CAUTION*
- If your job runs out of time before the data sync is complete, use `s3cmd sync --recursive --no-check-md5` to restart the sync process where it left off (even if the sync says complete)

*Or use `get`/`put`*:<br>
`s3cmd get s3://path/to/file /path/to/where/you/want/file/` - pull down single file<br>
`s3cmd put path/to/file s3://path/to/where/you/want/file/` - place a single file into bucket


## Using s5cmd
When working with large Tier 2 buckets, CDNI users may use the `s5cmd` client for operations such as `du` and `ls`. This is a CDNI-specific workflow that uses the shared installation available through the `faird` project space.
For general MSI Tier 2 access methods, see the [MSI File Storage documentation](https://userdocs.msi.umn.edu/storage/storage.html).

The usage is similar to s3cmd except that it requires the `--endpoint-url` argumement to specify MSI's S3 (Tier 2) instead of the default (AWS S3). For example: `s5cmd --endpoint-url https://s3.msi.umn.edu du -H s3://MY_BUCKET/*`

*Setup Required to use s5cmd*<br>
1. Add to your `.bashrc` (1) the path on MSI where it's installed, (2) the code needed for path completion (which can also be viewed with `s5cmd --install-completion`), (3) export your S3 credentials:

```
# path to s5cmd installed on MSI
export PATH=$PATH:/projects/standard/faird/shared/code/external/utilities/s5cmd
# prepare autocompletion suggestions for s5cmd and save them to COMPREPLY array
_s5cmd_cli_bash_autocomplete() {
	if [[ "${COMP_WORDS[0]}" != "source" ]]; then
		COMPREPLY=()
		local opts cur cmd
		cur="${COMP_WORDS[COMP_CWORD]}"
		cmd="${COMP_LINE:0:$COMP_POINT}"
		[ "${COMP_LINE:COMP_POINT-1:$COMP_POINT}" == " " ] \
			&& cmd="${cmd} ''" 
		opts=$($cmd --generate-bash-completion)
		while IFS='' read -r line;
		do
			COMPREPLY+=("$line");
		done \
		< <(compgen -o bashdefault -o default -o nospace -W "${opts}" -- "${cur}")
		return 0
	fi
}
# call the _s5cmd_cli_bash_autocomplete to complete s5cmd command. 
complete -o nospace -F _s5cmd_cli_bash_autocomplete s5cmd

# export S3 credentials from s3info
export AWS_SECRET_ACCESS_KEY=$(s3info | grep Secret | awk '{ print $NF }' )
export AWS_ACCESS_KEY_ID=$(s3info | grep Access | awk '{ print $NF }' )
```

## Updating S3 Policy & Bucket Access

To gain access to an existing CDNI Tier 2 bucket, ask the bucket owner or another user who already has permission to manage its access. If you are unsure who currently has access, consult the Tier 2 tab of CDNI's data tracking spreadsheet.

MSI maintains the general process for creating bucket policies and granting collaborators access. See [Reducing Tier 1 Footprint at MSI](https://userdocs.msi.umn.edu/storage/archiving_data.html) for the current MSI-supported workflow.

Within CDNI, we commonly use the `set_s3policy` and `get_x500.sh` utilities described below to manage access to existing shared buckets. 

1. If you haven't already done so, add the line `export PATH="/projects/standard/faird/shared/code/internal/utilities/s3policy_bin/:$PATH"` to your `~/.bashrc`and open a new terminal after saving your changes in order for your changes to take effect.
   
2. Print list of current users with bucket access with the command<br> `/projects/standard/faird/shared/code/internal/utilities/MSI-utilities/s3_get_x500/get_x500.sh s3://bucket_name/`
   
3. Copy the *FULL LIST* (see **NOTE** below), append the x500 for the new user you wish to grant access (x500_3 in the example below), and feed into the `set_s3policy` command like so, excluding the s3:// prefix for the bucket name in the command:<br> `set_s3policy x500_1,x500_2,x500_3 bucket_name FULL`
   
4. Finally, update the list of users with access to the bucket in tier2 tab of CDNI's [tracking spreadsheet](https://docs.google.com/spreadsheets/d/1QpKYJQqhuxoQhErBscAEev9npsd1RgKS8KdCL6FiuEo/edit?usp=sharing)

**NOTE: You must copy the full list from `get_x500.sh` because every time you set a policy you need to list EVERYONE that needs access. You CANNOT just list that one person's x500: this will result in only that person having bucket access and access removal for all other x500s, including the bucket owner. `get_x500.sh` will also list your x500 since you need to have access to the bucket in order to run this command.**

If you do not have access to the `faird` share, you can create your own `get_x500.sh` script with the following code: 

```
# Give full path to bucket (ex: s3://bucket-name/)
bucket=$1

x500=$( for uid in $(s3cmd info ${bucket} | grep -oE '([0-9]{5})'); do s3info -u ${uid} | grep 'Sharing' | cut -d \@ -f 1 | cut -d \: -f 2; done )

all_x500s=$(echo $x500 | sed 's| |,|g')

echo $all_x500s

```
